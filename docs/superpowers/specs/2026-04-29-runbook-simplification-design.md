# Runbook Simplification — Design

**Status:** Proposed
**Date:** 2026-04-29
**Item:** Release-readiness #6
**Tracking:** `docs/superpowers/handoff/prompt-item-6.md`

## Problem

`docs/guides/smoke-test-mvp-azure.md` is the de-facto deploy runbook. It is
451 lines, exhaustive, and was authored alongside a running findings log
(`smoke-test-mvp-azure-findings.md`, 724 lines, F1–F24) of every cliff one
of the maintainers fell off while following it. The lighter
`docs/guides/deploy-azure.md` exists in parallel but is incomplete and
contradicts the smoke-test doc in places.

PRD goal #1 — *"A Platform Engineer can stand up their first working
scheduled skill in one afternoon"* — is not met today. A first-time
operator hits at least these cliffs unaided:

- Required Bicep params not in `params.example.json` (F1, F2, F4)
- `ingressExternal` defaults to `false` and silently breaks GitHub webhooks (F3)
- Master-key generation undocumented (F4)
- No published GHCR image after a fresh checkout (F5, F9)
- GitHub App vs OAuth App confusion (F10)
- Postgres firewall blocks the operator's `admin init` (F16)
- KV PEM upload required as a separate post-deploy step (F7, F15)
- Container App revisions don't auto-heal after schema migration (post-init restart)

The release-readiness review's recommendation was *dramatically simplify* —
not "fix one thing." The runbook needs major step reduction plus
automation of the cliffs.

## Goal

A new self-hoster, with no project knowledge, can go from an empty Azure
subscription to a green run in under one afternoon (~2 hours) following a
single quickstart doc with no help.

## Mechanism

Two coordinated changes:

1. **A new `cronfoundry bootstrap azure` subcommand** that wraps the
   manual `az`/`openssl`/`gh` choreography of the current runbook into one
   interactive command. It generates secrets, writes a params file, runs
   the Bicep deploy, opens the Postgres firewall to the operator's IP,
   runs `admin init`, restarts the serve revision, and polls until
   `/healthz` is green.
2. **A rewritten quickstart doc** (`docs/guides/quickstart-azure.md`)
   with ≤10 numbered steps, where the deploy itself is one step
   (`run cronfoundry bootstrap azure`). The existing
   `docs/guides/deploy-azure.md` becomes the full reference for
   non-default deployments and troubleshooting.

The current `smoke-test-mvp-azure.md` is deleted; the findings file moves
out of `docs/` to `.smoke-history/2026-04-21-azure-mvp-findings.md`.

## Components

### `internal/bootstrap/azure/` (new package)

The bootstrap logic, isolated from `cmd/`. Each major step is its own
exported function so that unit tests can call them with a mock `Runner`.

```go
// Runner abstracts the shell-out so tests can stub it.
type Runner interface {
    Run(ctx context.Context, name string, args ...string) ([]byte, error)
    RunStreaming(ctx context.Context, name string, args ...string) error
    RunWithEnv(ctx context.Context, env []string, name string, args ...string) error
}

type Bootstrap struct {
    Runner Runner
    Stdin  io.Reader  // for prompts
    Stdout io.Writer
    Binary string     // path to the cronfoundry binary, used to shell out admin init
}

func Preflight(ctx context.Context, r Runner) error
func Prompt(ctx context.Context, stdin io.Reader, stdout io.Writer) (Inputs, error)
// MasterKey is generated by the cobra command via secretstore.GenerateMasterKey()
// and passed in on the Bootstrap struct.
func ProbeImage(ctx context.Context, owner, tag string) error
func WriteParams(in Inputs, masterKey, paramsPath string) error
func Deploy(ctx context.Context, r Runner, region, templateFile, paramsFile string) error
func AllowOperatorIP(ctx context.Context, r Runner, env, ip string) error
func AdminInit(ctx context.Context, r Runner, binary, dsn, masterKey, orgName string) error  // shells out to <binary> admin init
func RestartServe(ctx context.Context, r Runner, env string) error
func WaitHealthy(ctx context.Context, fqdn string, timeout time.Duration) error
func (b *Bootstrap) Run(ctx context.Context) error  // orchestrates the above
```

`Inputs` is a struct with fields for env suffix, region, GitHub App ID,
OAuth client id/secret, PEM path, admin login, Postgres admin password.

### `cmd/cronfoundry/bootstrap.go` (new file)

Wires the cobra command:

```text
cronfoundry bootstrap azure [--params-out PATH] [--non-interactive] [--dry-run]
```

`--non-interactive` reads inputs from env vars (documented per field) so CI
or automation can drive it. `--dry-run` performs preflight + prompts +
params-file write but skips the `az deployment` call. Default mode is
interactive.

### `deploy/params.example.json` (rewrite)

- `ingressExternal: true` (default that actually works for the documented
  flow)
- `imageTag: "latest"` with comment recommending pinning
- Replace `RUN_cronfoundry_admin_init_TO_GENERATE` with `""` and comment
  pointing to `cronfoundry bootstrap azure`
- All other params stay as placeholders the operator (or bootstrap) fills in

### `docs/guides/quickstart-azure.md` (new)

Target shape:

```text
1. Prerequisites (az, bicep, gh account, Slack webhook URL, one LLM key, two GH repos)
2. Register the GitHub App (with the GitHub-App-vs-OAuth-App callout from F10)
3. Clone + `make build`
4. (If no published image) Tag and push v<X.Y.Z>; wait ~5 min for the release workflow
5. `./cronfoundry bootstrap azure` — answer prompts; ~10 minutes
6. Bootstrap prints the FQDN; paste it into the GitHub App's three URL fields
7. Open https://<fqdn>/; log in; connect your skill repo; add three secrets in Settings (llm_key, slack_webhook, github_webhook_secret)
8. Push a sample `cronfoundry.yaml` + `SKILL.md` (templates inlined)
9. Wait ≤5 min for the first fire; verify Slack + GitHub issue + memory commit
10. Pass/fail checklist
```

Eight to ten numbered steps. Target wall time: 45 min for first-timer, ~25 min for someone who has done it.

### `docs/guides/deploy-azure.md` (revise)

Becomes the full reference doc:

- Every Bicep param described, with non-default values explained
- Custom domain / VNet / region selection
- Manual flow (for operators who can't run bootstrap)
- Troubleshooting section migrating selected items from F1–F24 as
  "if you see X, do Y" entries
- Upgrade and teardown procedures (currently the only thing in this doc)

### `docs/guides/smoke-test-mvp-azure.md` (delete)

Replaced by quickstart. The PR description links the deletion commit so

### `.smoke-history/` (new directory)

Move `smoke-test-mvp-azure-findings.md` here as

## Data flow

```text
operator
  │
  ├─▶ ./cronfoundry bootstrap azure
  │     │
  │     ├─ Preflight: which az; az account show; which bicep
  │     ├─ Prompt: env, region, GH App ID/clientID/clientSecret/PEM, admin login, pg password (gen if blank)
  │     ├─ GenerateMasterKey (crypto/rand 32B → b64)
  │     ├─ ProbeImage: HEAD ghcr.io/v2/gambtho/cronfoundry/manifests/<tag>; on 404 → exit with tag-push instructions
  │     ├─ WriteParams: deploy/params.<env>.json (PEM contents inlined as @secure param)
  │     ├─ Deploy: az deployment sub create --location <region> --template-file deploy/main.bicep --parameters @<paramsPath>
  │     ├─ AllowOperatorIP: api.ipify.org → az postgres flexible-server firewall-rule create
  │     ├─ AdminInit: shell out via Binary to `<binary> admin init` with CRONFOUNDRY_DATABASE_URL + CRONFOUNDRY_MASTER_KEY env
  │     ├─ RestartServe: az containerapp update --set-env-vars RESTART_TRIGGER=$(date +%s)
  │     └─ WaitHealthy: poll https://<fqdn>/healthz, 5-min timeout
  │
  └─◀ FQDN, login URL, three GitHub-App URLs to paste back
```

## Tests

### Unit (per `internal/bootstrap/azure/*_test.go`)

Stub `Runner` with a fake that returns canned stdout/stderr/exit codes per
command pattern. Cover:

- `Preflight`: az missing, az not logged in (non-zero `account show`),
  bicep missing → typed errors
- `Prompt`: env suffix validation (≤10 chars, no special chars),
  region empty defaults to `swedencentral`, postgres password URL-safe
  generator produces alphanumerics only
- `GenerateMasterKey`: 32 bytes, valid base64, distinct across calls
- `ProbeImage`: 200 → ok; 404 → typed error with the tag-push suggestion;
  non-2xx/4xx → wrapped error
- `WriteParams`: PEM with embedded newlines round-trips through JSON;
  every required Bicep param present in the written file;
  `ingressExternal: true`
- `AllowOperatorIP`: shell command shape and arg ordering
- `WaitHealthy`: returns on first 200; gives up after timeout

### Integration (gated `CRONFOUNDRY_E2E=1`)

`internal/bootstrap/azure/integration_test.go` exercises the full flow
against a real Azure subscription. Skipped under `-short` and absent the
env var. Documented in `deploy-azure.md` under "Maintainers" so that
periodic re-runs are scriptable.

### Manual

Maintainer (or, ideally, a fresh tester unfamiliar with the project) runs
the quickstart end-to-end before the PR merges. The PR body records:

- Who ran it
- Wall time start → green run
- Any step that needed help (those become bugs)

## Operational notes

- Bootstrap shells out to `az` rather than embedding the Azure SDK for Go.
  Reasons: zero new heavy dependencies in the binary, parity with what
  every Azure operator already has installed, simpler auth (operator's
  existing `az login` session).
- The `Runner` abstraction is what makes the package unit-testable; do
  not let `os/exec` calls leak into the step functions directly.
- Master key never written to disk except inside the Bicep params file.
  After deploy, the operator is reminded that re-running with a different
  key will make existing encrypted secrets unrecoverable.
- The PEM is pasted into the params file as a `@secure` Bicep param, so
  it lands in Key Vault during deploy. No standalone `az keyvault secret
  set` step (resolves F7, F15).
- Postgres firewall rule is named `cf-bootstrap-<UTC-yyyymmdd>` so
  repeated runs don't error on duplicate rule names; the rule is left in
  place after bootstrap finishes (operator can remove it manually). A
  note in the quickstart calls this out.
- Bootstrap does **not** auto-trigger a GitHub release. If the requested
  image tag is missing, it prints the exact `git tag … && git push origin
  …` commands and exits non-zero. This avoids assuming `gh` is installed
  or that the operator has push rights to the repo (which they wouldn't
  for the canonical fork).

## Cliff coverage matrix

For every F1–F24 finding, where it's now handled:

| Finding | Resolution |
|---|---|
| F1 (wrong param names) | Quickstart never lists params; bootstrap writes them. |
| F2 (missing required params) | Bootstrap writes all required. |
| F3 (`ingressExternal` default) | New default in `params.example.json`; bootstrap writes `true`. |
| F4 (master key generation) | `Bootstrap.GenerateMasterKey`. |
| F5 / F9 (no GHCR image; tag-stripping) | `Bootstrap.ProbeImage` errors with the right tag form. |
| F6 (visibility) | Documented in `deploy-azure.md` troubleshooting. |
| F7 / F15 (PEM upload) | Inlined as `@secure` Bicep param. |
| F8 (red main / staticcheck) | Already fixed on main. |
| F10 (OAuth vs GitHub App) | Quickstart §2 keeps the callout. |
| F11–F14, F17, F18, F19, F20–F23 | Already fixed in `main.bicep` per findings log; no action here. |
| F16 (Postgres firewall) | `Bootstrap.AllowOperatorIP`. |
| F24 (runner GitHub token) | Already fixed on main. |

Re-deploy revision restart is `Bootstrap.RestartServe`. Health verification
is `Bootstrap.WaitHealthy`.

## Out of scope

- A standalone `cronfoundry-bootstrap` binary. Same code; different
  packaging. Trivially extractable later if useful.
- Multi-cloud bootstrap (`bootstrap aws/gcp`). Reserved as future
  subcommands but not implemented.
- AKS / Fly.io adapters — separate docs already exist.
- Doc styling / branding refresh.
- Auto-triggering GHCR releases.
- Replacing the `az` CLI dependency with the Azure SDK for Go.
- A `cronfoundry diagnose` standalone subcommand. Verification is inline
  in `bootstrap`. May be revisited later.

## Acceptance criteria

1. `docs/guides/quickstart-azure.md` exists with ≤10 numbered steps.
2. Every required Bicep parameter has a working default in
   `params.example.json` or is filled in by `cronfoundry bootstrap azure`.
3. F1–F24 cliffs are each addressed per the matrix above; reading each
   finding against the new quickstart + bootstrap shows it's handled or
   pre-empted.
4. `docs/guides/smoke-test-mvp-azure.md` is deleted; the findings file is
   moved out of `docs/` to `.smoke-history/`.
5. PR body documents before/after step count and before/after estimated
   wall time, plus the result of at least one fresh end-to-end run.
6. New unit tests cover each `Bootstrap.*` step under a mocked `Runner`.
   `go test ./...` and `go vet ./...` pass; no new lint failures.
