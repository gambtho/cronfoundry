# Plan: E2E test job in CI

Spec: `docs/superpowers/specs/2026-04-30-e2e-ci-design.md`

The e2e suite already exists and meets the acceptance criteria. Only CI
wiring + a docs note is needed. No code in `cmd/`, `internal/`, or
`web/` is touched.

## Task 1 — Add e2e job to ci.yml

**File:** `.github/workflows/ci.yml`

Append a new job after `test`, before `build`:

```yaml
  e2e:
    runs-on: ubuntu-latest
    timeout-minutes: 20
    needs: test
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-go@v5
        with:
          go-version-file: go.mod
          cache: true

      - name: make e2e
        run: make e2e
```

Update the `build` job's `needs:` from `test` to `[test, e2e]` so the
container build waits on the full signal.

**Verification:**
- `yamllint .github/workflows/ci.yml` (if available) or visual check.
- `make e2e` locally still passes (no Makefile changes here, but sanity).

Commit message:
`ci: run end-to-end test suite on every PR`

## Task 2 — Document local run

**File:** `README.md`

Find the existing "Development" / contributor section. Add a short
subsection (just below the unit-test instructions if any, otherwise near
the bottom of the development block):

```markdown
### End-to-end tests

`make e2e` runs the `TestE2E_*` suite under the `e2e` build tag. It
boots throwaway Postgres containers via testcontainers and stubs the
LLM, Slack/Discord webhooks, and the git clone, so no external network
or real credentials are required — but Docker must be running.

CI runs the same target on every PR.
```

Place it consistently with the surrounding markdown style (heading
level matching other dev subsections).
