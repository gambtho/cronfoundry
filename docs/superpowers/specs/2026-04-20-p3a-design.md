# P3a — GitHub OAuth + Session Auth Layer

**Status:** Shipped (e74e651)

## Scope

P3a adds the human-auth layer that all later P3 dashboard work depends on:

- GitHub OAuth login / logout flow
- Signed session cookies (stateless, HMAC-SHA256)
- `requireSession` middleware for `/api/*` routes
- `GET /api/me` — the only data endpoint in this sub-plan
- Allowlist-based role assignment (`admin` / `viewer`) via env vars

P3a does **not** add any dashboard views, read-only data endpoints, or write surfaces. Those are P3b and P3c. P3a is shippable as a standalone PR that unblocks all later UI work.

## Architecture

### Package layout

A new `internal/webapi/` package sits alongside the existing `internal/api/`. Both register handlers on the **same `http.ServeMux`** in `cmd/cronfoundry/serve.go`. One listener, two namespaces, no second port.

```
internal/
  api/          ← existing, runner-facing (/internal/*)
  webapi/
    server.go       registers /api/* and /oauth/* routes on the shared mux
    session.go      Session struct + HMAC sign/verify helpers
    auth.go         requireSession middleware + SessionClaims context key
    oauth.go        GET /oauth/login, GET /oauth/callback, GET /oauth/logout
    me.go           GET /api/me
```

`webapi.Deps` carries the new auth fields. It does **not** embed `api.Deps` (avoid circular import); `serve.go` constructs the two dep structs independently from the same raw materials.

```go
type Deps struct {
    OAuthClientID     string
    OAuthClientSecret string
    AdminLogins       []string       // from CRONFOUNDRY_ADMIN_LOGINS
    ViewerLogins      []string       // from CRONFOUNDRY_VIEWER_LOGINS
    MasterKey         []byte         // for HMAC signing; same master key as token.Signer
}
```

`serve.go` constructs both `api.NewServer` and `webapi.RegisterRoutes(mux, deps)`, passing the same `*http.ServeMux` to both.

## OAuth Flow

### Endpoints

| Method | Path | Auth | Purpose |
|--------|------|------|---------|
| GET | `/oauth/login` | none | Initiate OAuth; set state cookie; redirect to GitHub |
| GET | `/oauth/callback` | none | Validate state; exchange code; set session cookie; redirect to `/` |
| GET | `/oauth/logout` | none | Clear session cookie; redirect to `/oauth/login` |
| GET | `/api/me` | requireSession | Return `{"login":"…","role":"…"}` |

### Login sequence

1. `/oauth/login` generates a 16-byte random `state`, stores it in a signed `oauth_state` cookie (10-minute TTL, `HttpOnly`, `SameSite=Lax`), and redirects to:
   ```
   https://github.com/login/oauth/authorize?client_id=…&state=…&scope=read:user
   ```
2. GitHub redirects back to `/oauth/callback?code=…&state=…`.
3. Handler verifies `state` query param matches `oauth_state` cookie (CSRF check). Mismatches → 400.
4. Exchanges `code` for an access token via `POST https://github.com/login/oauth/access_token`.
5. Fetches `GET https://api.github.com/user` with the access token to retrieve the GitHub login.
6. Checks login against `AdminLogins` then `ViewerLogins`. Not found in either → 403.
7. Creates a signed session cookie `cf_session` (24-hour TTL) and redirects to `/`.

### Session cookie format

```
cf_session = base64url(JSON{login, role, exp}) + "." + base64url(HMAC-SHA256(payload, masterKey))
```

Cookie attributes: `HttpOnly`, `SameSite=Lax`, `Secure` when the listener address is not `127.0.0.1`/`localhost`.

The master key (already required in production via `CRONFOUNDRY_MASTER_KEY`) is reused for HMAC signing — no new secret material needed.

## Session Middleware

`requireSession` reads `cf_session`, verifies the HMAC signature, checks expiry, and attaches `SessionClaims{Login, Role}` to the request context. Returns `401` for missing/invalid/expired cookies.

```go
type SessionClaims struct {
    Login string
    Role  string  // "admin" or "viewer"
}
```

`SessionClaimsFromContext(ctx)` follows the same pattern as the existing `ClaimsFromContext` in `internal/api/auth.go`.

All `/api/*` routes in P3b+ will be wrapped with `requireSession`. In P3a only `/api/me` uses it.

## Environment Variables

Four new vars, validated at startup in `serve.go`:

| Var | Required | Description |
|-----|----------|-------------|
| `CRONFOUNDRY_GITHUB_OAUTH_CLIENT_ID` | yes | GitHub OAuth App client ID |
| `CRONFOUNDRY_GITHUB_OAUTH_CLIENT_SECRET` | yes | GitHub OAuth App client secret |
| `CRONFOUNDRY_ADMIN_LOGINS` | yes (≥1 entry) | Comma-separated GitHub logins with admin role |
| `CRONFOUNDRY_VIEWER_LOGINS` | no | Comma-separated GitHub logins with viewer role |

Missing `CLIENT_ID`, `CLIENT_SECRET`, or empty `ADMIN_LOGINS` → `serve` exits immediately with a descriptive error, matching the pattern for `CRONFOUNDRY_MASTER_KEY`.

No new database tables. No schema migration. P3a is purely additive Go code + env vars.

## Testing Strategy

### Unit tests (`internal/webapi/`)

- `session_test.go` — sign/verify round-trip; expiry rejection; tampered-signature rejection
- `oauth_test.go` — state cookie generation; CSRF validation (matching and mismatching state); allowlist check (GitHub HTTP calls stubbed with `httptest.NewServer`)
- `auth_test.go` — `requireSession` middleware: valid cookie → passes through; missing cookie → 401; expired → 401
- `me_test.go` — `/api/me` returns correct JSON for admin and viewer claims

No Postgres needed — the session layer is stateless.

### Integration test

Extend `cmd/cronfoundry/serve_test.go` with a test that boots the full server (real mux, no DB needed for `/api/me`), constructs a hand-crafted valid session cookie signed with the test master key, and asserts `/api/me` returns 200 with correct JSON. Verifies end-to-end mux wiring.

## What Does NOT Change

- `internal/api/*` — runner-facing handlers are untouched
- `internal/scheduler/*`, `internal/runner/*`, `internal/cloud/*` — untouched
- Database schema — no new tables or columns in P3a
- Existing env vars — no renames or removals
