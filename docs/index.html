Why existing tools fall short

        

          

            
🔒

            
Locked to one provider

            
Claude Routines and ChatGPT Tasks don’t support GitOps config, multi-destination outputs, or self-hosting. Your prompts and keys live in their cloud.

          

          

            
🔧

            
Reinventing the wheel

            
Generic cron + shell scripts work, but every team rebuilds prompt management, secret handling, output formatting, and observability from scratch.

          

          

            
🌐

            
Too general-purpose

            
n8n, Zapier, and Power Automate treat LLM steps as an afterthought. Config lives inside the tool, not in git. No streaming, no token accounting.

          

        

      

    


    
    

      
How it works

      
Three steps from config to team-visible output.

      

        

          
1

          
Define in YAML

          
Declare your skill path, schedule, provider, and destinations in cronfoundry.yaml. Lives in your repo, reviewed like code.

          


skills:
  - path: skills/digest
    schedules:
      - cron: "0 9 * * MON"
        provider: openai
        destinations:
          - slack:
              secret: slack_url

          

        

        

          
2

          
Runs on schedule

          
CronFoundry fires the skill at the configured cron, streams a completion from your LLM provider, and parses any <memory> blocks.

          


Streaming: gpt-4o-mini
tokens: 1 243
cost:    $0.0009
status:  succeeded

          

        

        

          
3

          
Output lands everywhere

          
Results publish in parallel to GitHub issues, Slack, Discord, or Teams. Learnings commit back as cronfoundry[bot].

          


✓ GitHub issue #142
✓ #eng-digest (Slack)
✓ Writeback → memory.md
  (cronfoundry[bot])

          

        

      

    


    
    

      

        
Use cases

        
What teams are already building with CronFoundry.

        

          

            
📋

            
Weekly digest

            
Engineering digest

            
Summarizes last week’s activity and posts to a GitHub issue + Slack. Next week’s run has context because learnings commit back to memory.md.

          

          

            
🚨

            
Daily brief

            
On-call handoff

            
Reads yesterday’s alerts, generates a structured handoff, and posts an Adaptive Card to the on-call Teams channel every weekday at 08:30.

          

          

            
🔍

            
Weekly triage

            
Backlog grooming

            
Reviews the GitHub project board, identifies stale items, and files an issue with suggested actions — no manual triage required.
