# P3c — Write Surfaces

**Status:** Approved
**Date:** 2026-04-20
**Author:** gambtho (brainstormed with Claude)

## Overview

P3c adds the write surfaces to the CronFoundry dashboard: schedule pause/resume and run-now, secret management (create/rotate/delete), and repo connect/disconnect via GitHub App installation. All writes are inline actions on existing pages plus one new Secrets page.

## Scope

**In scope:**
- Schedule pause/resume and manual run-now trigger
- Secret create, rotate, delete (write-only; values never read back)
- Repo connect via GitHub App installation OAuth callback
- Repo disconnect (removes repo_connection + cascade)
- Audit logging for all mutating actions

**Out of scope:**
- Editing schedule config (cron, destinations, provider) — GitOps only; YAML is source of truth
- GitHub App installation picker — GitHub's own UI handles "all repos" vs "select repos"
- Dark mode, mobile layout — deferred

## Architecture

P3c extends `internal/webapi` with new write handlers alongside the P3b read handlers. No new pages except Secrets — writes are inline actions on the Repos, Schedules, and new Secrets pages. The GitHub App installation callback reuses the `/oauth/` route pattern from P3a but handles the App installation flow rather than user login.

All mutating handlers:
1. Require `RequireSession` middleware (admin role enforced for writes)
2. Write an `audit_log` row (actor = GitHub login, action, target kind + ID)
3. Return appropriate HTTP status (200/201/204 on success, 4xx on client error)

## API Endpoints

All under `/api/*` or `/oauth/*`, all requiring session auth.

```
POST /api/schedules/{id}/pause
  — Sets schedule.enabled = false. Idempotent. Audit-logged.
  — Response: 204 No Content

POST /api/schedules/{id}/resume
  — Sets schedule.enabled = true. Idempotent. Audit-logged.
  — Response: 204 No Content

POST /api/schedules/{id}/run-now
  — Inserts run row (fire_reason=manual), dispatches runner via JobDispatcher.
  — Response: 201 { "run_id": "<uuid>" }
  — Audit-logged.

GET  /api/secrets
  — Lists secrets: name, created_at, updated_at, last_used_at. No values returned.
  — Response: Secret[]

POST /api/secrets
  — Body: { "name": string, "value": string }
  — Writes to secretstore. Returns 409 if name already exists.
  — Response: 201 { "name": string }
  — Audit-logged.

PUT  /api/secrets/{name}
  — Body: { "value": string }
  — Rotates secret (new version in secretstore). Returns 404 if not found.
  — Response: 200 { "name": string }
  — Audit-logged.

DELETE /api/secrets/{name}
  — Soft-deletes secret in secretstore. Returns 404 if not found.
  — Response: 204 No Content
  — Audit-logged.

GET  /api/repos/connect
  — Redirects browser to GitHub App installation URL:
    https://github.com/apps/{APP_SLUG}/installations/new
  — APP_SLUG read from config/env.

GET  /oauth/app-callback
  — GitHub redirects here after App installation with ?installation_id=&setup_action=
  — Verifies the installation belongs to the authenticated user's GitHub account
    (fetches /user/installations from GitHub API using the session's OAuth token;
    rejects with 403 if installation_id is not in that list — prevents CSRF on callback).
  — Fetches installation repositories via GitHub App API.
  — Upserts repo_connection rows for each repo granted.
  — On success: redirects to /repos
  — On error (cancelled, missing param): redirects to /repos?error=installation_cancelled
  — Audit-logged (action: repo.connect, one entry per repo upserted).

DELETE /api/repos/{id}
  — Removes repo_connection row + cascades: deletes associated skill and schedule rows.
  — Does NOT revoke the GitHub App installation (user must do that from GitHub).
  — Confirmation required at UI layer (not enforced server-side).
  — Response: 204 No Content
  — Audit-logged.
```

## UI Changes

### Schedules page (extended from P3b)

Each schedule row gains two inline actions:
- **Pause / Resume toggle button** — single click, no confirmation. Optimistic UI update (flip badge immediately, revert on error with toast).
- **Run now button** — single click. On success (201), navigate to the new run's detail page. On error, toast.

### Repos page (extended from P3b)

- **"Connect repo" button** in page header → `GET /api/repos/connect` → browser redirects to GitHub.
- On return from `app-callback`, page reloads at `/repos`. If `?error=installation_cancelled` is present, show a dismissible error banner.
- Each repo row gains a **"Disconnect" button** → confirmation dialog: _"This will remove all skills and schedules for this repo. Are you sure?"_ → `DELETE /api/repos/{id}` → remove row from list on success.

### Secrets page (new, in left-nav between Repos and Schedules)

Table columns: name, last updated, last used. Three actions:

- **"Add secret" button** (page header) → inline form below header: name field + password-type value field + Save/Cancel. On 409, show inline field error "A secret with this name already exists."
- **"Rotate" button** per row → inline form replacing the row: password-type value field + Save/Cancel. Clears form on success, shows updated timestamp.
- **"Delete" button** per row → confirmation dialog → `DELETE /api/secrets/{name}` → remove row.

Values are never displayed after creation. The rotate UX is paste-new-value only.

## Error Handling

| Scenario | Behavior |
|---|---|
| Pause/resume/run-now failure | Revert optimistic update; toast with server error message |
| Secret create 409 (name conflict) | Inline field error: "A secret with this name already exists" |
| Secret create/rotate 400 | Inline field error with server message |
| Secret not found on rotate/delete | Toast: "Secret not found — it may have been deleted" |
| Repo connect cancelled by user | Banner on /repos: "GitHub App installation was cancelled" |
| Repo disconnect failure | Toast with error message; row remains |
| 403 on any request | Redirect to /oauth/login |
| 500 on any request | Toast: "Something went wrong. Please try again." |

## Audit Log

Every mutating action writes an `audit_log` row:

| Action | target_kind | target_id |
|---|---|---|
| `schedule.pause` | `schedule` | schedule UUID |
| `schedule.resume` | `schedule` | schedule UUID |
| `schedule.run_now` | `run` | new run UUID |
| `secret.create` | `secret` | secret name |
| `secret.rotate` | `secret` | secret name |
| `secret.delete` | `secret` | secret name |
| `repo.connect` | `repo_connection` | repo_connection UUID |
| `repo.disconnect` | `repo_connection` | repo_connection UUID |

Actor is the GitHub login from the session.

## File Layout

```
/internal/webapi/
  schedules_write.go     # pause, resume, run-now handlers
  secrets.go             # list, create, rotate, delete handlers
  repos_write.go         # connect redirect, app-callback, disconnect
  server.go              # RegisterRoutes extended with new endpoints

/web/src/
  pages/
    Secrets.tsx           # new page
  components/
    ConfirmDialog.tsx      # reusable confirmation dialog
    InlineForm.tsx         # reusable inline form (used for secret create/rotate)
  api/
    schedules.ts          # pause/resume/run-now mutations
    secrets.ts            # CRUD mutations
    repos.ts              # connect + disconnect mutations
```

## Testing

- **Go:** handler unit tests for each write endpoint using `httptest` + `internal/testdb`. The `app-callback` handler is tested with a mock GitHub API (similar pattern to existing `internal/github` tests using recorded fixtures).
- **Frontend:** Vitest for mutation helpers. Manual testing for the GitHub App installation flow (requires a real GitHub App).

## Success Criteria

An operator can:
1. Pause and resume a schedule from the Schedules page.
2. Trigger a manual run and be navigated to the new run's detail page.
3. Create a secret, rotate it, and delete it — values never visible after creation.
4. Click "Connect repo", install the GitHub App on a repo, and see the repo appear in the Repos list.
5. Disconnect a repo with confirmation and see it removed from the list.
